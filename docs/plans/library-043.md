# ReplayLite 0.4.3 — библиотека повторов и шапка

## Цель и границы

Запрос: исправить обрезанную версию после обновления, обновлять значок панели задач, добавить библиотеку клипов по отдельной кнопке возле настроек и убрать две нижние кнопки главной страницы. Карточки по референсу: превью, длительность, имя/дата/размер, открытие, показать в папке, копирование пути и удаление в корзину с подтверждением.

База main d9f446d, VERSION 0.4.2, Git чистый. Windows/.NET Framework 4.8, существующие FFmpeg/ffprobe и Lucide. Новые runtime-зависимости не добавляются. Системное перетаскивание не изменять и не проверять по прямому указанию пользователя. Установленная копия/клипы пользователя не изменяются тестами.

Пользователь уточнил: значок не меняется при смене темы; воспроизведение нужно внутри ReplayLite. Плеер использует имеющийся FFmpeg и NAudio, один процесс только во время просмотра, ограниченные кадры/PCM; пауза, перемотка, громкость, остановка при выходе/скрытии. Копирование кадров в CPU относится только к явному просмотру клипа, путь записи GPU/NVENC не меняется. Выбор общей компоновки настроек из предыдущей задачи не относится к библиотеке.

## Проверки

Обязательны build/check-build, check-buffer/audio/capture-recovery, package/check-deployment/check-installer. Новые тесты библиотеки используют отдельные локальные файлы и синтетический валидный клип; реальные пользовательские файлы не удалять. Кнопка удаления сначала спрашивает подтверждение, использует корзину; не откатываться к безвозвратному удалению при ошибке корзины.

При просмотре: два превью на странице, последовательная обработка, отмена при скрытии/переключении/выходе. Пустая папка и битое видео — штатные состояния. Экспорт во время просмотра добавляет клип без повторного кодирования; старые кадры/настройки/микрофон не меняются. Встроенное воспроизведение зависит от ответа пользователя.

Ресурсы: библиотека закрыта (CPU/RAM/процессы), открытие/перелистывание/закрытие после прогрева, ограниченность кеша и дескрипторов, три сопоставимых прогона без движения окна. Проверка GPU/VRAM/FPS игры не заменяется соседними метриками; неизмеренное указать.

## Находки и изменения плана

Пользователь подтвердил полную видимость версии и смену значка панели задач в тестовой копии, затем уточнил положение: название не должно смещаться вниз ради версии; версия непосредственно над последней «e». Шапка дополнена кешируемыми видимыми границами глифов: центр текста совмещён с логотипом, версия расположена над центром последней буквы с зазором 1 px. Маски измеряются только при изменении текста/шрифта/DPI, постоянной работы нет.

- Реальный тест выявил отказ плеера при записи в созданный именованный канал: FFmpeg считал выход уже существующим. Для принадлежащего плееру канала добавлен `-y`; видео/звук, пауза, seek и скрытие после исправления дошли до следующего сценария.
- При удалении тестового файла пойман AccessViolation в COM DeleteItem: передача объекта как IUnknown вместо IShellItem. Интерфейс заменён типизированным IShellItem; требуется повтор реальной корзины и всей библиотеки. Тестовые отчёты сохраняют промежуточные подтверждения перед нативной операцией.
- Для динамических карточек обнаружено удержание Dispose-контролов в локализации и tooltip. Подписки/словарь очищаются; WeakReference-тест подтвердил сборку старых карточек после перелистывания.

Позиция версии в 0.4.2 менялась из SizeChanged/FontChanged соседнего контрола: при DPI-масштабировании это может повторно масштабировать координаты и обрезать версию. Нужно убрать зависимость от порядка масштабирования: рисовать название и версию в одной области с зарезервированным местом. Значок Form.Icon уже менялся, но закреплённый Shell-значок может использовать ресурс EXE/ярлыка; не считать повторное присваивание Icon доказательством исправления TaskBar.
