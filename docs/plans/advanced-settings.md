# План: расширенные настройки ReplayLite

## Цель и границы

### Уточнение пользователя: навигация и уникальность расширенных параметров

В ходе реализации пользователь потребовал убрать вкладки, открывать настройки шестерёнкой и возвращаться закруглённой стрелкой. План скорректирован до дальнейших правок: убрать верхние вкладки и внутренние вкладки категорий; расширенный экран сделать прокручиваемым с заголовками групп. FPS/битрейт остаются только в обычных настройках. Расширенный экран содержит только дополнительные параметры: курсор, устройства/громкость, папку/запас места, анимации и уведомления. Навигация назад: расширенные → обычные → запись. Размер окна сохраняется. Автоматические проверки навигации и снимки будут обновлены и выполнены на новой сборке.

Дополнительные шаги: P3 повторно `in_progress` для новой навигации; затем P4/P5 — свежая сборка, сценарии возврата/прокрутки, регрессии, живой NVENC, замеры, пакет и deployment/installer. Ранее выполненные проверки сохраняются как история, но не заменяют проверку новой версии интерфейса.

Второе уточнение: убрать повторяющиеся кнопки сброса и растянутые интервалы. План: одна кнопка «Сброс» внизу расширенных настроек, сброс всех дополнительных параметров без изменения обычных; во время записи общий сброс заблокирован. Уменьшить высоту полей и расстояния, оставить короткие однострочные описания. Повторно проверить прокрутку, размещение контролов и сохранность обычных параметров при общем сбросе.

Третье уточнение: удалить все описания с экрана, оставить подписи и значения; стрелка назад без фоновой плашки; собственный зелёный scrollbar без системной белой полосы. Удалить большую кнопку обновлений, перенести действие на логотип с подсказкой и индикатором новой версии. Обычный клик логотипа открывает существующее окно обновления; скачивание остаётся отдельным явным действием. После правок проверить навигацию, мышь/колесо/перетаскивание собственной прокрутки и состояния обновления. Фоновые таймеры не добавлять.

Четвёртое уточнение по снимку: заменить тесное системное поле пути буфера на скруглённое поле в стиле приложения, с иконкой папки, читаемым текстом/ellipsis и выровненной кнопкой «Изменить». Для стандартного пути показывать «По умолчанию»; полный путь — в tooltip. Переключатель анимаций управляет короткими переходами основного окна, а не FPS видео.

Итоговый объём: настройки в существующем окне 760×480 через шестерёнку и стрелку назад, без вкладок; компактный дополнительный экран без описаний с собственной зелёной прокруткой, ползунками и единственным сбросом. Логотип открывает обновления. Исходная ветка `main`, база `9600451`, рабочее дерево на старте было чистым. Новые библиотеки и релиз не требуются.

FPS/битрейт остаются только в обычных настройках. Дополнительные параметры: выбранные аудиоустройства, раздельная громкость, курсор, папка буфера и порог остановки по свободному месту, анимации и уведомления. Настройки записи применяются после остановки буфера, общие допускаются во время записи. Автозапуск остаётся в обычных настройках. GPU-масштабирование проверено и исключено после ошибки закреплённого фильтра; CPU-замена не добавляется. HEVC/AV1, отдельные дорожки и оверлей вне задачи.

## Найденные дефекты, ограничения и результаты

Заполняются по фактическим проверкам. Записи и пользовательские настройки остаются вне Git.

Финальные доказательства и ограничения: [отчёт проверки](../ADVANCED-SETTINGS-VALIDATION.md). Программные изменения отправлены в `main` коммитом `323bdfa`, версия поднята коммитом `8d3aed9`. Выпуск завершён: [v0.3.16](https://github.com/DraimCiDo/ReplayLite/releases/tag/v0.3.16), стабильный Latest, CI и опубликованные SHA-256 проверены. Подробности — в [закрытом плане выпуска](release-0.3.16.md). Исходный отчёт проверки 0.3.15 сохранён как историческое доказательство этапа разработки.

- Закреплённые зависимости загружены с проверкой SHA-256. Системная ExecutionPolicy не менялась: `-ExecutionPolicy Bypass` используется только у дочернего процесса сборки/тестов, поскольку запуск файлов в этой среде по умолчанию запрещён.
- База собрана из отдельного `git archive HEAD` в изолированной Portable-копии. Три запуска `--ui-test` и `--self-test ... none 10 0 0` завершились с кодом 0. CPU приложения + FFmpeg: 0,27 / 0,16 / 0,21% всех логических процессоров; пиковый working set: 154,3 / 150,7 / 150,6 МиБ. Это короткая запись рабочего стола с буфером 10 секунд, 2560×1440, 30 FPS, 8 Мбит/с, без звука; не игровая нагрузка. Во всех прогонах два MP4 полностью декодированы.
- `scale_d3d11` имеется в FFmpeg 9.0.2, но реальная цепочка DDA → scale_d3d11 → NVENC не создаёт GPU-текстуру (`80070057`) даже при фиксированном 1280×720, NV12/BGRA. Выбор разрешения исключён из реализации; оставлена явная подпись исходного разрешения. CPU-масштабирование не добавлено. Дополнительно реализовано включение курсора DDA/WGC.
- Первая сборка обнаружила зависимость общей темы от MainForm в отдельной сборке IconTool; исправлено через общий интерфейс предпочтений анимации без зависимости от формы. После исправления сборка и первый UI-тест прошли. Проверки расширены для настоящего PCM pipe, ошибок папки и имитации малого свободного места; требуется повторный запуск свежей сборки.
- Последующие сборка и `check-build/buffer/audio/capture-recovery` прошли с кодами 0. `--advanced-live-test` проверил реальный NVENC, явные аудио-endpoint, громкость 50%, выключенный курсор, пользовательскую папку буфера и сохранение. MP4 H.264 2560×1440 + AAC 48 кГц stereo полностью декодирован, код 0.
- В отдельном настоящем окне проверены мышь на ползунке, клавиша End (битрейт 30), ввод громкости 45% с Enter, навигация и переключатель анимаций. Просмотрены четыре снимка финальной сборки; исправлен фон кнопок хранения, расширены числовые поля для 10240 МБ. Выбор конкретного endpoint фильтрует события других устройств; добавлена регрессия.
- Первые замеры UI показали дополнительную память при раннем создании расширенных контролов. Страница переведена на создание при первом открытии, без перечисления устройств при обычном запуске; отсутствие ранних контролов проверено UI-тестом. Базовые замеры сохранены; финальные три прогона выполняются отдельно после оптимизации.
- Первый `package.ps1` завершился ошибкой совместного доступа к только что скопированному исходному ZIP NAudio в тестовом staging-каталоге. Это блокировка файлов окружения, а не ошибка приложения. Защита Windows не меняется; после замеров будет повторный запуск штатного скрипта из кеша. Проверки deployment/installer ещё не выполнялись.
- Повторная упаковка воспроизвела тот же отказ на исходном ZIP FFmpeg. Установлена причина: модуль Windows PowerShell Archive читает файлы через `File.Open(..., Open, Read)` с эксклюзивным sharing. Упаковка переведена на существующий .NET `ZipFile.CreateFromDirectory` с временным архивом и заменой готового файла только после успеха. Добавлен `AGENTS.md` в пакет, чтобы ссылка из README не обрывалась. Нужны проверка shared-reader фикстуры и полный package/deployment/installer на свежем EXE.
