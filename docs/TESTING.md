# Проверка изменений ReplayLite

## Среда и выполнение

Используйте Windows x64, существующий компилятор .NET Framework 4.8 и PowerShell. Для настоящего захвата требуется NVIDIA с NVENC и доступный рабочий стол. Подготовка закреплённых зависимостей: `source/setup-deps.ps1`; запускайте её только при отсутствии нужных файлов. Она скачивает зависимости и проверяет SHA-256. Не обновляйте версии ради проверки другой задачи.

Команды выполняются из корня проекта. Установите UTF-8 и прекращение выполнения при ошибке:

```powershell
$ErrorActionPreference = 'Stop'
$OutputEncoding = [Console]::OutputEncoding = [System.Text.UTF8Encoding]::new($false)
```

Каждый скрипт запускайте отдельным процессом существующего `powershell.exe` или `pwsh`, например:

```powershell
& powershell.exe -NoProfile -File .\source\build.ps1
$checkExit = $LASTEXITCODE
if ($checkExit -ne 0) { throw "build.ps1 failed: $checkExit" }
```

Тот же способ используйте для `check-*.ps1`. Не меняйте системную ExecutionPolicy. Сохраняйте код каждого процесса сразу: последующая команда может перезаписать `$LASTEXITCODE`. Отсутствие отчёта, таймаут и необработанное исключение — сбой проверки. Проверяйте, что отчёт создан текущим запуском; старый `PASS` не принимается.

## Существующие проверки

В 0.4.2 UI-проверки дополнены фоновой проверкой обновлений с детерминированной фикстурой (интервал/офлайн/отключение в полёте/дедупликация/конечное мигание), видимостью кнопки только на главном экране, геометрией названия/версии, фактическим путём буфера, холодным запуском цвета битрейта и контрастом четырёх полных палитр. 20 смен палитры после прогрева проверяют GDI/USER-дескрипторы. `--advanced-live-test` дополнительно меняет язык и все темы при настоящей записи и проверяет сохранение пользовательского кириллического имени. Это не тест физического перетаскивания.

Для меню из шести вкладок `check-build.ps1` также проверяет переключение разделов, подсказки и темы, блокировку параметров записи, независимое включение микрофона, автосохранение новых параметров, единый сброс, закрытие с выходом, безопасные шаблоны имён и генерацию сигнала с громкостью 0/100. Собственная прокрутка проверяется с искусственно увеличенным содержимым; в компактном меню без переполнения полоса скрыта.

Аппаратный режим `ReplayLite.exe --preferences-hardware-test <папка отчёта>` проверяет H.264/HEVC/AV1, MP4/MKV, CBR/VBR, масштабирование 1080p/720p, микрофон отдельно от системного звука, отказ экспорта без потери буфера и восстановление AV1 после завершения собственного FFmpeg. Нужны монитор на NVIDIA, поддержка всех трёх кодеков и доступный рабочий стол; этот режим не предназначен для runner без GPU. Запуск и ограничения: [SETTINGS.md](SETTINGS.md).

После изменения программы обязательны свежая сборка и базовые автоматические проверки ниже. Если проверка недоступна, укажите блокировку вместо успеха. Список нужен для выбора и исполнения, эти строки не являются отчётом о запуске.

| Порядок / команда | Что проверяет | Условия и ограничения |
| --- | --- | --- |
| `source/build.ps1` | Компиляция приложения, helper, uninstaller, иконок и версии | Нужны `NAudio.dll` и существующий csc; это не поведенческий тест |
| `source/check-build.ps1` | Версия EXE и встроенные UI-проверки | Запускает `--ui-test`, отчёт `.deps-cache/ui-test.txt`; не аппаратный захват |
| `source/check-buffer.ps1` | Синтетический буфер, неудачный экспорт, очистка использованных сегментов, отсутствие общих кадров, продолжение записи и декодирование | Реальный FFmpeg, синтетическое видео, без NVIDIA; отчёт в новой `.deps-cache/buffer-test-*/` |
| `source/check-audio.ps1` | Смоделированные отказы и восстановление источников | Без физических устройств; отчёт `.deps-cache/audio-test-*/audio-test.txt` |
| `source/check-capture-recovery.ps1` | Смоделированные сбои захвата и восстановление | Без реального GPU-захвата; отчёт `.deps-cache/capture-recovery-*/capture-recovery-test.txt` |

Для правок установки, обновлений, путей, состава пакета или удаления дополнительно выполните в указанном порядке:

1. `source/package.ps1` — собрать свежие Portable ZIP и установщик после сборки EXE. Требует закреплённый Inno Setup и исходные архивы зависимостей, может обращаться к сети.
2. `source/check-deployment.ps1` — проверки развёртывания, обновления и отката на тестовых файлах; нужны свежие `dist/ReplayLite-Setup.exe`, `dist/ReplayLite-Portable.zip` и `UpdateHelper.exe`.
3. `source/check-installer.ps1` — настоящий установщик в тестовых каталогах, отдельная тестовая регистрация HKCU и ярлык; скрипт очищает их. Это изменение тестового окружения, не установка рабочей копии пользователя.

Перед запуском прочитайте затронутый тест: покрытие определяется утверждениями в коде, а не названием файла. Добавляйте проверку нового значимого поведения в соответствующий существующий набор. Не создавайте тесты, которые лишь повторяют реализацию или проверяют заранее заданный вывод.

## Выбор сценариев

В плане выберите применимые строки, укажите шаги, ожидаемый результат и способ проверки. Неприменимость обоснуйте. Один успешный путь не закрывает строку целиком.

| Область | Рабочие и граничные случаи | Ошибки и восстановление |
| --- | --- | --- |
| Запись и экспорт | Пустой/частичный/полный буфер; повторные клипы; сохранение при продолжающейся записи; остановка при сохранении | Повторное сохранение одновременно; недоступная папка; отказ FFmpeg; буфер сохранён при ошибке, после устранения причины экспорт работает |
| Файлы и настройки | Пути с пробелами и кириллицей; сохранение/повторный запуск; Portable/installed | Некорректные значения, повреждённый файл, запрет записи, исчезнувший каталог; понятная ошибка без потери пользовательских данных |
| Звук | `both`, `system`, `none`; тихий источник; выбранный режим сохранён | Потеря микрофона/вывода/обоих; возврат устройств; видео продолжается, доступный звук сохраняется, источник восстанавливается |
| Захват | Каждый доступный монитор; поворот; DDA и резервный WGC | Потеря доступа, завершение/зависание процесса, смена разрешения, сон/возврат; совместимый буфер сохранён, несовместимый сброшен с сообщением, повторы ограничены |
| UI и ввод | Кнопки/трей/горячая клавиша дают одинаковый результат; многократное открытие списков и вкладок | Занятая клавиша, отмена ввода, скрытие/закрытие окна, быстрые повторные действия; hook и анимации освобождены, элементы отражают реальное состояние |
| Запуск и выход | Запуск в трей, открытие без второго процесса записи, штатный выход | Устройства не готовы; ограниченные повторы; выход во время восстановления/экспорта; нет осиротевшего FFmpeg |
| Обновление и установка | Оба режима, сохранение настроек и MP4, перезапуск | Нет сети, таймаут, повреждённый ZIP/хеш, выход пути за каталог, блокировка файла, откат; рабочая версия и пользовательские данные сохранены |
| Ресурсы | Простой, скрытое окно, запись, экспорт, повторные циклы | Ошибки/восстановление не создают бесконечный опрос, рост памяти, дескрипторов или процессов; см. [методику](PERFORMANCE.md) |

Не заполняйте реальный диск, не отключайте защиту, не удаляйте пользовательские файлы и не завершайте процессы по одному имени ради негативного теста. Имитируйте нехватку места/прав/устройств в изолированной фикстуре. Реальное отключение устройств и сон выполняйте только когда это входит в задачу и не мешает рабочему сеансу. Если сценарий проверен только имитацией, так и напишите.

## Реальная запись и артефакт

Для изменений захвата, аудио, буфера и экспорта нужна проверка настоящего NVENC в дополнение к синтетической. Для UI нужна проверка настоящего окна; автоматические границы контролов не заменяют визуальную проверку изменившегося экрана. Используйте тестовую копию приложения, отдельные настройки и каталог внутри `.deps-cache/`. Не запускайте одновременно тесты, использующие общий файл настроек, горячую клавишу или окно.

Встроенные аппаратные режимы: `--self-test <каталог> <both|system|none> <секунды> <output> <adapter>`, `--ui-live-test <каталог>`, `--startup-test <каталог>`, `--capture-recovery-live-test <каталог>`. Индексы output/adapter берите из фактического перечисления мониторов. Перед запуском сверяйте аргументы с `source/ReplayLite.cs` и `source/SelfTest.cs`. Эти режимы могут захватывать экран/микрофон и менять настройки тестовой копии; они не должны запускаться для одной документационной правки.

`--advanced-live-test <каталог>` дополнительно проверяет настоящую запись через окно с выбранными аудиоустройствами, громкостью 50%, выключенным курсором и папкой буфера с пробелами/кириллицей. Отчёт — `<каталог>/ui-live-test.txt`; полученный MP4 отдельно проверяется ffprobe и полным декодированием. `--advanced-screenshot <PNG> <0|1|2|3>` создаёт снимок соответствующего раздела без запуска записи.

В `--ui-test` включены `AdvancedSettingsTests`: навигация шестерёнкой и закруглённой стрелкой без вкладок, прокрутка компактных групп, совместимость настроек, автосохранение и единый сброс дополнительных параметров с сохранением обычных настроек, блокировка записи, отсутствие таймеров при выключенных анимациях, реальные PCM pipes с громкостью 0/50/100%, выбранный отсутствующий endpoint и фильтрация чужих уведомлений, пользовательская папка, отказы сохранения и имитация малого свободного места при запуске и работе. Это не физическое отключение устройств.

EXE запускайте через `Start-Process -PassThru -WindowStyle Hidden`, задавайте конечный таймаут, проверяйте `ExitCode`, свежий отчёт и отсутствие `FAIL`. Завершайте при таймауте только созданный тестом процесс. Для видимого UI-теста откройте тестовое окно и проверьте его состояние.

Для полученного MP4 проверьте потоки и длительность через `bin/ffprobe.exe`, затем полностью декодируйте файл:

```powershell
& .\bin\ffmpeg.exe -v error -xerror -i '<тестовый-файл.mp4>' -f null -
$decodeExit = $LASTEXITCODE
if ($decodeExit -ne 0) { throw "Decode failed: $decodeExit" }
```

Подставьте настоящий тестовый путь. Дополнительно проверьте ожидаемые изображение, ориентацию и звук; успешное декодирование не доказывает правильность содержимого и синхронизации. Записи, TS, настройки и полные личные логи не включайте в Git. В отчёте оставляйте обезличенные результаты. После теста остановите созданные процессы и восстановите изменённые настройки; перед удалением тестового дерева проверьте его абсолютный путь.

## Только документация

Проверьте локальные ссылки, соответствие имён файлов и команд исходникам, согласованность обязательных правил, отсутствие выдуманных запусков и секретов, diff и кодировку UTF-8. Сборка и аппаратная запись не требуются, пока исходники, зависимости и поведение не изменены.
