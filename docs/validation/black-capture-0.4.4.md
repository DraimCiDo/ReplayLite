# Проверка восстановления чёрного захвата — 0.4.4

Дата: 7 ноября 2026. Исходная версия: main `6a7dc0c`, ReplayLite 0.4.3. Рабочая установленная копия, её настройки и сохранённые записи не изменялись. Проверки выполнены в отдельной portable-копии.

## Симптом и установленные дефекты

В проблемном MP4 настоящий H.264 High/yuv420p, 2560×1440: `blackdetect` обнаружил чёрное изображение с 0 до 173,03 секунды. Перекодирование/другой плеер не восстанавливают отсутствующую картинку. Свежие изолированные DDA/WGC-захваты на этом же оборудовании дают изображение. Точная причина отказа во время игры не воспроизведена.

Установлено: наличие живого FFmpeg и новых сегментов ошибочно считалось достаточным признаком здоровья; анализ содержимого отсутствовал. Кроме того, SessionUnlock ускорял только уже запланированное восстановление, не пересоздавая живой повреждённый захват.

Добавленный UI-регрессионный тест запущен с исходным обработчиком SessionUnlock: `check-build.ps1` завершился с кодом **1**, ошибка `Unlock did not restart a live capture session.` После восстановления исправления — код **0**.

## Автоматические проверки

`source/build.ps1`, `check-build.ps1`, `check-library.ps1`, `check-buffer.ps1`, `check-audio.ps1`, `check-capture-recovery.ps1`, `check-capture-image.ps1`: код выхода **0**. После финального изменения путей захвата повторены затронутые UI/image/recovery-проверки и аппаратная проверка, также код **0**.

Image-test использует настоящий синтетический кодер H.264, который сначала выдаёт чёрные сегменты без завершения процесса. Проверяются оба направления переключения, сохранение работающего процесса до подтверждения, настоящий тёмный источник, повтор одного сегмента, ограничение частоты, отмена, освобождение процессов и наличие изображения в экспортированном клипе после восстановления. Результат резервного источника в этой проверке подставной — GPU здесь не проверяется.

## Настоящее оборудование

Windows 11 Pro 10.0.26300; Ryzen 7 5700X, 16 логических процессоров; RAM 31,9 GiB; RTX 4060, драйвер 32.0.16.2101; FFmpeg 9.0.2 essentials. Основной неповёрнутый монитор 2560×1440, H.264/NVENC, 30 FPS, 8 Mbps, без аудио.

`--capture-image-live-test`: тестовое окно с красным, зелёным, синим и жёлтым полями. DDA/native, DDA/720, WGC/native, WGC/720: захват, экспорт MP4 и полное декодирование успешны, четыре цвета проверены по известным координатам с допуском на сжатие. Дополнительно финальный режим проверяет настоящую команду одноразового probe резервного GPU-источника.

## Ресурсы

Три сопоставимых коротких прогона `--self-test ... none 10 0 0` каждой версии, включая заполнение и полный оборот 10-секундного кольца, повторные сохранения, декодирование и остановку во время сохранения. Новая версия выполняет обычную проверку изображения в цикле self-test. Существующая рабочая запись и прочие фоновые приложения оставались запущенными; интерактивная сцена не полностью детерминирована, результаты не являются игровым бенчмарком.

| Метрика | 0.4.3, три прогона | 0.4.4, три прогона |
| --- | --- | --- |
| CPU приложения + основного FFmpeg, % всех 16 потоков | 0,29 / 0,33 / 0,23 | 0,29 / 0,33 / 0,34 |
| Пиковый working set приложения + основного FFmpeg, MiB | 165,4 / 166,6 / 165,4 | 148,8 / 149,6 / 148,8 |
| Пик дискового кольца, MiB | 14,2 / 14,0 / 14,0 | 14,0 / 14,3 / 14,0 |

Диапазоны CPU пересекаются; эти короткие измерения не доказывают отсутствие любой регрессии. Метрика self-test не включает краткоживущий декодер проверки изображения, поэтому его стоимость измерена отдельно на native-клипе: три запуска одного кадра дали CPU 62,5 / 46,875 / 62,5 мс, стеновое время с запуском 151 / 101 / 107 мс и выборочный пик working set 17,5 / 19,0 / 19,0 MiB. Каждый результат — 2304 байта (64×36). Нормальный интервал — не чаще 30 секунд; дополнительный GPU-probe запускается только при подтверждении чёрных сегментов. Постоянного декодера и загрузки каждого кадра на CPU нет.

Не измерены GPU/VRAM, игровой FPS/1% low и многочасовая стабильность. Преимущество перед конкурентами не заявляется.

## Ограничения поведения

Это восстановление молчаливого отказа при наличии работающего резервного источника. Если оба API возвращают чёрное изображение, переключения нет: настоящая тёмная сцена не должна вызывать цикл перезапусков. Защищённое содержимое и блокировку захвата игрой исправление не обходит. Подтверждение занимает до двух 30-секундных интервалов плюс закрытие сегмента. После успешного переключения сбрасывается неисправный кольцевой буфер, сохранённые клипы остаются нетронутыми.

Физическая блокировка/сон и конкретная игра в этой проверке не воспроизводились. Обработчик разблокировки проверен имитацией события через настоящий UI message loop.
