# Проверка меню настроек — 29 октября 2026

Предварительная реализация для одобрения пользователем. VERSION/EXE остаются 0.3.16/0.3.16.0. Тег и релиз 0.4.0 пока не создаются по прямому условию задачи.

## Среда и исходники

Windows 11 Pro 10.0.26300, Ryzen 7 5700X / 16 логических CPU, 31.9 GiB RAM, NVIDIA RTX 4060, драйвер 32.0.16.2101. Запись 2560×1440; FFmpeg 9.0.2, NAudio 1.10.0, .NET Framework 4.8. Проверка изображений при масштабе 100%.

База — сохранённый до правок EXE из чистой main 24d0860 (код приложения соответствует 0.3.16), SHA-256 `8FC54DD63B4E11D896D2AE8DA0325F782A1AF0A1623DBB6D3759B38D4A9DAF08`. Окончательный EXE: `09D38285590A7B97FE1CC6BB664FCD5DC49A8676F9267CAAAFF788D686CC9DF7`.

Все проверки выполнены в изолированных Portable-папках `.deps-cache/settings-redesign-*`. Установленная копия и её текущая запись не останавливались; это ограничивает сравнение общего GPU и влияния на игру. Новые зависимости не добавлялись.

## Ресурсы

Обычный путь — native, H.264 NVENC, 30 FPS, 8 Мбит/с, без аудио; буфер 10 секунд. `--self-test` измеряет Recorder и FFmpeg без MainForm, выполняет повторные экспорты, декодирование и остановку. Это не замер полной программы с открытым окном и не игровой benchmark. CPU нормализован на все 16 логических процессоров. Working set не равен private bytes или VRAM.

| Метрика | База, три прогона | Окончательная сборка, три прогона |
| --- | --- | --- |
| CPU, % всех CPU | 0.22 / 0.28 / 0.26; медиана 0.26 | 0.36 / 0.27 / 0.31; медиана 0.31 |
| Пиковый working set Recorder + FFmpeg, MiB | 165.7 / 148.8 / 148.7; медиана 148.8 | 149.3 / 148.8 / 148.7; медиана 148.8 |
| Пиковые сегменты на диске, MiB | 14.3 / 14.0 / 14.2 | 14.3 / 14.0 / 14.0 |

Разброс CPU исследован дополнительным контрольным прогоном **исходного EXE после новых прогонов**: 0.38%, RAM 149.0 MiB, диск 14.0 MiB. Параметры FFmpeg для native получены из обоих Recorder через тестовый launcher и сравнены побайтно — **совпадают**. Предварительные чередующиеся прогоны новой сборки также давали 0.28 / 0.35 / 0.27%. Нагрузка зависит от рабочего стола и работающей установленной копии; эти короткие измерения не доказывают ни ускорение, ни устойчивую CPU-регрессию. Числа не скрыты и не заменены выгодным прогоном. RAM и границы кольца сохранились. Для строгого сравнения CPU/GPU и игрового frame time нужен отдельный контролируемый сеанс.

Скрытый настоящий MainForm без записи, прогрев 3 секунды + 15 секунд измерения, по три прогона: CPU-счётчик не изменился у обеих сборок (это предел короткой выборки, а не нулевой расход ресурсов). У обеих — **0 активных анимаций**. Working set базы 40.49–40.55 MiB; новой сборки 40.43–40.46 MiB. Новые разделы создаются только при первом открытии, постоянных таймеров не добавлено.

Масштабирование 1080p/720p — согласованный пользователем компромисс: копирование кадров и масштабирование через CPU. Оно явно отмечено в интерфейсе и отключено по умолчанию. Превосходство над конкурентами, VRAM/GPU и влияние на FPS игры не измерялись. Длительная работа, старые GPU без HEVC/AV1, портретный монитор и масштабы DPI выше 100% не объявляются проверенными.

## Исправления в ходе проверки

- `scale_d3d11` возвращал 80070057; D3D12 interop не поддержан. По ответу пользователя реализован явный CPU-вариант с предупреждением вместо неработающих GPU-пунктов.
- AV1 не помещается в MPEG-TS: для него выбраны Matroska-сегменты, включая очистку, объём, экспорт и восстановление.
- Убраны тёмная нижняя полоса и начальные старые цвета элементов в светлой теме; поле имени оформлено как остальные поля. Повторный визуальный осмотр подтвердил результат.
- Несовместимый NVENC больше не превращается в бесконечное восстановление. Отдельный процесс-фикстура с `[av1_nvenc] Codec not supported` отвергается с понятной ошибкой без повторов; DDA/EOF остаётся восстанавливаемым.
