Актуализация 29 октября 2026: изменения 0.4.2 описаны в docs/RELEASE-042-VALIDATION.md и docs/plans/ui-042.md. Не повторяй готовое: отдельная кнопка обновлений только на главном экране, автопроверки раз в 5 минут с ограниченной индикацией, новая типографика (версия над концом названия), переписанные RU/EN-подсказки без повторного заголовка, реальный путь буфера, удаление выбора вывода и мягкие полные темы. Работай в локальном репозитории ReplayLite-main, в текущей рабочей папке. Общайся по-русски. Сначала прочитай AGENTS.md, docs/AGENT-WORKFLOW.md, TESTING.md, PERFORMANCE.md, docs/plans/ui-performance-localization.md и актуальный отчёт 0.4.1. Проверь Git и существующие изменения. Составь полный план с критериями приёмки до правок. Помощников не запускай без явного запроса.

Пользователь попросил выпустить готовые изменения сегодня, а оставшуюся работу продолжить завтра. Не повторяй весь редизайн с нуля и не отменяй полезные исправления.

Что уже сделано в 0.4.1:
- Убраны настройка «Анимации интерфейса», таймеры переходов и надпись «Изменения сохранены».
- Отключённые подписи и поля отрисовываются цветами темы; есть тесты четырёх палитр.
- Официальные Lucide SVG закреплены commit be09619c1c1124ad09c19fc3e87ee3b939409bbd. SVG преобразуются в атлас при сборке, Bitmap кешируются. Лицензия сохранена. Не возвращай нарисованные вручную иконки и не подключай JS/runtime-загрузку иконок.
- Новый знак square-play, тематические состояния трея (простой, запись, сохранение, ошибка, обновление). Обновление отмечается только в трее.

- RU/EN интерфейс, меню, подсказки, сообщения, сохранение выбора языка. Переключение не перезапускает запись; пользовательские пути и имена не переводятся. Новые тесты покрывают переключение, меню, сохранение языка и целостность имени клипа.

Уточнение следующей сессии, 29 октября 2026: пользователь заметил похожий рост CPU при быстром перетаскивании других приложений Windows. Не считать штатную нагрузку системного цикла дефектом ReplayLite без сопоставления. Новый профиль, отклонённый эксперимент WM_MOVING и текущие шаги — в docs/plans/041-continuation.md. Не повторять замену промежуточного RECT: она нарушила движение и не включена в программу. Для выбора подготовлены макеты «Строки», «Сетка», «Секции» в docs/design/settings-variants.html; выбор пользователя ещё требуется.

Открытое исследование — CPU при физическом перетаскивании окна даже без записи.
Пользователь сам воспроизвёл его в отдельной Portable-копии:
- База 0.4.0: 4.924% CPU / 7.973 с / 5763 сообщения перемещения; 4.694% / 9.799 с / 7139 сообщений.
- Первая правка: 5.083% / 4.246 с / 3679 сообщений; 4.756% / 6.550 с / 6007 сообщений. Скорость перемещения была выше, поэтому эти проценты напрямую не сравнимы. Пользователь субъективно отметил снижение нагрузки и нормальное движение, но полного устранения замеры не доказали.
- WindowMotion.cs объединяет только повторные уведомления WM_WINDOWPOSCHANGED для чистого перемещения в нативном цикле до 60 Гц; реальная позиция окна средствами Windows не ограничивается. При WM_EXITSIZEMOVE вызывается UpdateBounds. Изменения размера, frame/visibility и неподвижные события обходят оптимизацию. Эти условия и конечные координаты покрыты тестом.
- Не объявляй CPU исправленным по одному удачному прогону или меньшей скорости мыши. Сравни не менее трёх прогонов при одинаковой частоте событий; учитывай CPU на 1000 событий, общее CPU, latency и paint/non-client сообщения. Сначала найди оставшийся источник нагрузки.
- Программное перемещение с обычным Timer не воспроизводило 4–5% и не заменяет физическое перетаскивание. Диагностические helpers/логи находятся в .deps-cache/ui-refresh-baseline и ui-refresh-candidate, исходники DragProbe.cs, UiMotionProbe.cs и UiFastMoveProbe.cs — в .deps-cache. Не включай сырые пользовательские данные и записи в Git.
- Не добавляй sleep в UI-поток, постоянный опрос мыши, неограниченные очереди или скрытые ограничения записи/FPS. Не обходи важные Win32-сообщения без проверки DPI, двух мониторов, активации, отмены перетаскивания, минимизации, shutdown и работы записи.

Дизайн, который нужно предложить пользователю:
1. Подготовь несколько действительно разных вариантов компоновки инпутов, ползунков и переключателей. Пользователь хочет сам выбрать вариант; не закрепляй окончательную компоновку без выбора. Подойдут компактные строки «название слева — значение справа», плотная сетка с подписями сверху, секции с общими переключателями/радиокнопками. Сохраняй разумный размер окна, читабельность, клавиатуру и оба языка.
2. Одновременно предложи варианты объяснений: всплывающая панель при наведении на название без вопросика; Lucide-справка вплотную к названию; короткая подпись/раскрываемое пояснение. Оформи в стиле приложения, проверь подсказки у отключённых параметров. Не возвращай стандартный белый tooltip.
3. Доведи заголовок окна: один стиль в активном и неактивном состоянии, без белого заголовка в тёмной теме. Исследуй настоящий Mica/Backdrop на поддерживаемой Windows; не используй прозрачность всего окна или постоянную перерисовку ради имитации. Предусмотри простой тематический fallback на старой Windows/при отключённых эффектах. Если меняешь на собственную шапку, сохрани перетаскивание, DPI, клавиши, минимизацию и штатное закрытие в трей.
4. Оцени новый логотип на 16/20/32 px и в трее; при необходимости предложи более узнаваемую оригинальную композицию на основе Lucide. Сохрани все четыре темы, все состояния и отметку обновления только в трее. Значок EXE статичен, а окно и трей должны менять палитру во время работы без утечек HICON/Bitmap.
